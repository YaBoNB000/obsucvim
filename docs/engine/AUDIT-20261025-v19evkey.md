# 静态强度审计：v19 evkey 件（2026-10-25）

> 对象：R079 引擎 + 完整加固构建的 mid 规模样本。仓库内 v16–v19-check 已随 §34 删除，
> 本审计用同一构建参数现生成等价件（结构同族、仅 payload/种子不同）。
>
> ```bash
> # 样本生成（R079 发布 wasm）
> node web/tools/wasi-runner.mjs '{"wasmPath":"<repo>/web/tools/obsucvim.wasm",
>   "workDir":"/tmp/v19","args":["--preset","v15","--env-check","--bind-executor",
>   "--seed","20261025","/work/kkksu-mid.lua","/work/kkksu-mid.v19evkey.hard.lua"]}'
> # 183,620 B / sha256 867b925a1694108780e41b80…
> ```
>
> 判定口径：**不执行任何 Lua、不引入任何运行时值**，只读产物字节。
> 复现工具：`web/tools/static-unpack-probe.py`。

---

## 1. 结论

**该件不构成「静态断钥」。** 载体层密钥流是产物内常量的纯函数，用 60 行 Python
即可解出；EVKEY/executor 绑定在本样本里只是**一道 fail-fast 门**，没有进入
解密数据路径。R1（运行时值入钥流）与 R4（host delta 入钥流）在本构建中
未体现在被审计的车道上。

---

## 2. 发现（按严重度）

### V-01 载体层静态可解（严重）

- 形态：`R[78]`/`R[73]` 两个 450 字符 base94 长串 + `R[112]`/`R[118]` 两张 48 项
  常量表 + `R[82]` 三阶 LCG + 每 5 字符解 4 字节的 XOR 层。
- 密钥来源：`[16]=264998881-92467504`（种子）、`[64]=266076561-98914605`（一次性加数）、
  `[61]/[20]/[44]/[74]`（XOR 基与步长）——**全部是产物内字面量**。
- 证据：探针解出 360 B，可打印率 1.000，且解出文本中出现产物内 `Ng` 转义表的
  **19 次 token 命中**（`xzwwB/xS52F/xCtBP/…`）；该 token 在原始长串里计数为 0，
  属内部一致性证明——不是巧合。
- 影响：第三方无需 mock、无需插桩即可进入第二/三层。

### V-02 密钥材料以可折叠字面量算术发射（严重）

| 位置 | 表达式 | 折叠值 |
| --- | --- | --- |
| `R[16]` | `264998881-92467504` | 172531377（LCG 种子） |
| `R[64]` | `266076561-98914605` | 167161956（一次性加数） |
| payload 乘子 | `246708231794+42616528915-289324760552` | 157 |
| payload 步长 | `259575738488+1045474088934-1305049827343` | 79 |

产物内同类减法常量共 **180 处**。一次常量折叠 + 一次代数化简即可恢复全部
初始量与步长，折叠本身不构成防护。

### V-03 运行时秘密未进数据路径（严重，与 R1/R4 宣称不符）

- `[64]` 全文只出现两次：一处是字面量定义，一处是 `S[64]=nil`。**没有任何探针写入它**。
- EV 探针（`getgenv` → `Vector3`/`typeof`/`game.IsStudio`/`checkcaller`/`identifyexecutor`）
  的返回值只用于两件事：
  1. `if not(as and q(Ve)=="number") then error("[Obsucvim] this executor lacks APIs…")`；
  2. 作为元组第 9 项传入装载器（`{PO,fr,ru,ms,Si,fold(d),wO,bI,zR}`）。
- 对照实验：同源码同 seed，`OBSUCVIM_V19_EVKEY=0` → 182,349 B；`=1` → 183,620 B。
  差异只落在常量抽取与探针夹具，**载体/字节码车道的可解性不变**。
- 影响：EV 的真实作用是「缺 API 时干净拒绝」，不是「错钥静默死亡」；
  静态攻击者不经过该门。

### V-04 语义表明文（高）

35 处 `s(95,95,112,111,119)` 这类十进制字符码调用，直接还原 VM 全部词汇：
`__pow __add __mod __div __unm __sub __concat __len __index __newindex __call __eq __lt __le`
+ 全部错误文案（`attempt to index a `、`attempt to perform arithmetic on a ` 等）
+ `char/byte/pack` + 字母表分片 `A/Z/0/_`。字符串表等于零防护。

### V-05 原生原语表明文（高）

模块表直接暴露：`buffer.{fromstring,tostring,readf32,readi32,len,writeu8,writeu32,writei8,copy}`、
`bit32.{bxor,band,bor,extract}`、`("").{byte,char,sub}`、`string.{match,find,gmatch,gsub,unpack,rep}`、
`table.{concat,move}`、`setmetatable/rawget/select/error/assert/xpcall`，
键位固定（如 `[59]=bit32.bxor`、`[18]=("").char`）。指令 handler 可按原语反查。

### V-06 诱饵可机械判别（中）

88 个 wrapper **全部**以同一签名开头：

```lua
NAME=function(A,B,...) local X=B[13]~=nil and N or M; return <const>,B,... end
```

`B[13]` 在所有真调用里恒为 `nil`（状态表无 13 槽），故整句是常量死码；
一行正则即可剔除全部诱饵，同时成为定位模块表与真解码器的锚点。
诱饵与真实代码比例约 2:1，但**判别成本为零**，等于把噪声变成了路标。

### V-07 R6「家族化」退化为常量条件（中）

- `if X~=Y then … else …`：10 处，两侧均为字面量（如 `24~=210`、`94~=190`）。
- `… and N or M`：133 处。

这些是本应提供「形态多态」的位置，实际发射成**恒定可折叠**的残句：
既不加人工成本，又形成稳定指纹。

### V-08 噪声可折叠（中）

`local ji=9742+7221; local gn=ji*298-4491; if gn*gn>=0 then local II=gn-ji end; local II=gn+1-1`
——`gn*gn>=0` 恒真、`gn+1-1` 恒等，全部一条折叠规则清空。

### V-09 计时守卫缺席（低，确认既有结论）

全文 `os.clock` 出现 **0 次**，时钟从未采样；与 `ENGINE-VERSION` §11.2「CLK 门恒不触发」一致。

### V-10 元特征稳定（低）

水印首行、单行 183 KB、1,613 个 `local`、390 个 `function`、8 个长串容器 ——
足以把任意新样本归类到「Obsucvim v15」并直接套用现成解析器。

## 3. 修复优先级

1. **V-03 + V-01**：让运行时量真正落在解密路径的不可逆位置（编码侧也要吃到同一个量），
   并给出负样本证据：「拔掉探针 → 解不出/解错」。这是唯一能改变存在性的改动。
2. **V-02**：密钥材料禁止以可折叠表达式出现；改为间接引用 + 跨表拼接。
3. **V-04 + V-05**：语义表、原语表分片、运行时装配，禁止整表明文化。
4. **V-06 + V-07**：诱饵形态多态（去掉 `[13]~=nil` 单签名）；「家族化」必须产出
   不可常量折叠的形态，否则不如删除（省体积）。
5. **门禁**：把 `static-unpack-probe.py` 扩成正式回归（先补字节码车道），每轮构建跑，
   红灯即失守；当前基线 = `STATIC BREAK`。

---

## 4. 诚实边界

- 本探针覆盖**载体车道**；字节码/常量段车道（`bdec`/`CDEC`）尚未实现，因此本文
  证明的是「存在静态可解入口」，不是「全量可解」。
- 未在真 Delta 上验证解出内容的语义正确性（本地无 Luau 运行时，不在本轮范围）。
- 审计对象为**现生成等价件**；用户真件（`Kkksu-mid.v19evkey.hard.lua`）建议按同一
  探针复核一次，确认结论一致。
