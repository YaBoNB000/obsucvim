# 稳定防绕过研究（增量53，2026-09-22）

> 背景：增量52 断崖协议（双因子碎链）在真执行器出现「常量解 nil」，
> 四轮诊断未能定位，按用户指令整体回退。本文档做根因复盘，并给出
> **以稳定为第一约束**的防绕过方案。

## 1. 增量52 为什么不稳定——根因复盘

增量52 在常量钥匙流里叠加了第二环境因子 T2（独立参数的
`tostring(Vector3.new(...))` 折叠）。失败的结构性原因不是某个实现
bug，而是设计层面的**镜像对齐风险**：

1. **每个运行期环境探针用作钥匙因子，就在构建期创建一个镜像**。
   编码侧按镜像期望值预补偿，解码侧按运行期实际值剥除——两侧必须
   逐位一致。T2 的镜像依赖 `tostring(Vector3)` 的**字符串格式**在
   「Rust 构建期假设」与「目标执行器实际行为」之间完全一致。
   格式、字段访问形态（`["X"]` vs `.X`）、数值表示，任何一处差异
   ⇒ 解码错钥。这类差异在本地（CLI Luau + 桩）**不可见**——只在
   真执行器暴露。
2. **新钥匙路径 = 解码正确性的新故障面**。常量解码是程序正确性的
   命脉，往里加新因子的收益（抗绕过）与风险（正确性）直接对冲。
3. **诊断成本不对称**：错位发生在「编码侧烘焙值 × 运行期值」之间，
   两侧都不在可见层，定位只能靠逐轮真机取证（52 花了四轮未闭环）。

**结论**：不稳定不来自「防绕过」这个目标，而来自「新增运行期环境
探针进钥匙流」这个手段。

## 2. 稳定性原则（从 51 成功 / 52 失败中归纳）

- **P1 镜像必须整数精确**：钥匙因子的构建期镜像只允许整数算术
  （51 的令牌折叠全是整数，52 的 T2 含字符串格式 ⇒ 违反）。
- **P2 只用真执行器实证过的探针**：51 的认证探针组（transcript 六折
  + 宿主语义）已在真执行器打通；任何新探针在实证前不得进钥匙流。
- **P3 失败必须安全**：错钥 ⇒ 垃圾输出，绝不 crash/nil/挂起
  （52 的 nil 是失败形态失控的直接表现）。
- **P4 开关字节级零影响**：关闭时必须与现役产物逐字节一致。
- **P5 可诊断性**：钥匙流改动必须带本地可验的对齐自检
  （不能再出现「只有真执行器才能发现错位」）。

## 3. 威胁模型与现状盘点（51 基线）

| 攻击面 | 51 现状 | 缺口 |
|---|---|---|
| B1 执行器内活体转储（解码结果） | 惰性解码缩窗 + 帧级缓存 | 同运行内转储仍可行（物理极限，R004） |
| B2 钥匙快照跨运行重放 | SALT 每运行新生（地址折叠）⇒ 已免疫 | 无 |
| B3 碎片转储+自建环境仿真 | 需完整仿真执行器语义 | 门槛已高（51 正面战场） |
| B4 部分重建（解一块够用） | 无结构约束 | 有缺口 |
| B5 单因子突破（令牌破=全破） | 块/常量两面共享同一令牌折叠系数 | 有缺口 |

**B2 已免疫的论证**：SALT = boot 期新表地址折叠，每运行必变、文件
零落盘；块钥匙与常量池钥匙都含 SALT ⇒ 捕获的钥匙流跨运行即失效。
52 想解决的其实是 B4/B5，手段选错了。

## 4. 稳定方案（增量53 = 钥匙面独立化）

**机制**：块钥匙面与常量池钥匙面的令牌折叠**改用独立系数族**：
- 块面（SLT）：`XTFB = XTOK*xm1 + xm2`（51 原样）
- 常量面（CDEC 基线）：`xtok2*xm3 + xm4`（新独立系数）
- 编码侧烘焙 `XTE_C = token*xm3 + xm4` 进常量基线（与块面 `XTE`
  并列，各自独立）

**性质**：
- 满足 P1（纯整数镜像）、P2（零新探针）、P3（错钥=垃圾）、
  P4（开关零影响）、P5（本地矩阵 + 负例可验）；
- 攻击者通过块面钥匙提取预言机拿到的折叠**推不出**常量面折叠
  （系数独立）——B5 的「破一面=破全面」降级为「每面单独攻」；
- 不引入任何新运行期计算路径（探针调用次数、调用点与 51 完全相同）
  ⇒ 52 类错位**在结构上不可能发生**。

**诚实评估**：两面仍同源于同一令牌值——拿到令牌本体的攻击者两面
都能算。本方案抬的是「部分钥匙泄漏/单面预言机」场景的成本，不是
令牌本身的强度。令牌强度由 51 的认证门负责（执行器语义仿真门槛）。

## 5. 备选目录（暂不实施，诚实标注价值与风险）

| 方案 | 价值 | 稳定性风险 | 结论 |
|---|---|---|---|
| 每原型独立钥匙盐 | B4 部分重建门槛↑ | 盐存 EP 表 ⇒ 转储可见，非秘密 | 价值虚，不做 |
| AV/SALT 再掩令牌 | 跨运行多态↑ | SALT 已每运行 ⇒ 重复建设 | 不做 |
| 缓存-探针绑定失效 | 跨状态复用防御 | CDEC 缓存本就帧级新生 ⇒ 无的放矢 | 不做 |
| AONT 替代位置掩码 | 理论边界↑ | 同 52 类新钥匙路径 | 冻结 |
| 反插桩强化（计时守卫参数） | B1 成本↑ | 误伤慢机风险需实测 | 可选项，独立增量 |

## 6. 物理极限（诚实边界）

执行器内活体观测（B1）无法在 Lua 层根除——被使用的值必须以明文
存在于某处（R004 定律）。稳定路线的目标不是「不可破」，而是：
① 把攻击从「拿一次钥匙/转储一次」抬到「必须完整仿真执行器语义并
全程活体插桩」；② 部分成果不可组合（钥匙面独立）；③ 跨运行成果
不可复用（SALT 每运行）。51 + 53 覆盖这三条，且不引入 52 类风险。

## 7. 验证口径（增量53）

- 开关关闭：与 51 产物逐字节一致（cmp 实证）
- 全矩阵：169/169 + 370/370 + multiseed + 守卫 6/6
- 裸 Luau/半吊子桩：毒杀 + 无泄漏（负例不退化）
- 真执行器：诊断靶（51 字母编号机制）正面验证 + 正式靶输出逐字
