## 3. 两项未闭环发现

### A. 变参末尾 nil 的语义不一致（已复现，正确性缺陷）

最小输入：

```lua
local function count(...) return select("#", ...) end
print(count(nil, "tail", false, 7, nil))
```

源程序输出 `5`；R064 VM 产物（seed `64066`）输出 `4`。当前 `makefn_decl` 先执行 `local all = { ... }`，再用 `#all - npa` 计算变参数量；Lua/Luau 表中存在洞或尾部 nil 时，`#` 不能可靠代表实参数量。现有矩阵通过，但未覆盖这个“显式尾部 nil”的情形。

本次上传的 7KB 样本没有把 nil 放在变参列表末尾，所以样本自身等价；此通用语义缺陷**尚未修复**，建议下一步让参数计数使用精确的 vararg 个数（并添加回归用例）。

### B. Micro-shard 执行期仍可插桩（白盒动态观察面）

在 `/tmp` 的临时生成器副本里，只在 micro shard 解码出 `op,x,y` 后加入探针，再用这份 7KB 源运行。一个生成器插入点被复制到 5 个 shard，记录到 **907,040 条**执行期记录（输出日志约 62.8 MB），且正常结果行仍出现。探针观察到微码三元组及 shard/参数/局部状态。

这证实 at-rest descriptor 封存不等于运行态不可观察：掌握运行中代码插桩能力的人仍可收集**已执行路径**。它没有恢复原始变量名/逐字源码，也不包含未执行分支；临时探针和 trace 产物均未放入仓库，未改动发布生成器。

## 4. 风险边界

本次 7KB 示例不加载外部代码，已做源/产物运行等价；审计不涵盖完整 Roblox/executor 环境。之前的 NOL 示例仍依赖 `loadstring(game:HttpGet(.../main/Wind.luau))` 这种未固定版本的远程依赖，应单独做供应链审查。当前 R064 的变量名压缩是体积/形态优化，不是新的密码学安全边界。
