## 1. 变参尾部 nil：修复与验证

旧 `makefn_decl` 先做 `local all={...}`，再用 `#all - npa`（legacy 为 `#all - pf.nparams`）算变参数量。表尾 nil/表洞下 `#` 不保证等于实参个数，导致转发及 `select("#", ...)` 少计。

**已实施**：v15 与 legacy 路径都在构造 `all` 前，以捕获的 `SEL("#", ...)` 取精确实参总数，再减去固定参数数量；`vargc` 作为独立计数沿调用与 vararg 表传递，不从含 nil 的表推断。v15 的 `makefn` 位于单独 RTFRAG 闭包，故从已有随机槽 `P[slots[12]]` 捕获 `SEL`；legacy 使用外层已捕获的 `SEL`。未新增全局查找、共享 getter 或密钥/描述符表。

`stress_multival.lua` 已加入直接尾 nil、固定参数+变参、转发、`return ...` 尾展开和嵌套闭包回归。seed `64066` 下 v15 与 legacy VM 的最小复现均返回 5；完整矩阵及多种子回归通过。

## 2. Micro-shard 动态追踪：发现与方案

H5-P0 已封存静态 `{program,mask,step}` descriptor 表；但执行时仍要从 packed/session carrier 解出三字节记录，`micro_shard_source` 随后在局部作用域使用 `op,x,y` 并调度。该函数还持有 shard offset、`E`、`O`、临时 `T`、VM 寄存器/常量表等上下文。

在 `/tmp` 的临时生成器副本中，于 `op,x,y` 解码后插入探针，7KB 样本曾产生 **906,284 条**实际执行记录、覆盖 4 个 shard，正常结果仍出现。此为白盒插桩证据，不是对未修改产物的自动脱壳；只覆盖已执行路径，不推得未执行分支或源变量名。

这是客户端模型的观察边界：有同进程代码插桩能力的观察者最终可记录正在执行的值。建议分层增加成本，而非承诺“阻止 trace”：

1. **信任边界**：密钥、授权、经济/反作弊等高价值决策放服务端；客户端混淆只计成本。
2. **保留 at-rest/session 防护**：维持 H5-P0 的 packed carrier、每 shard key 与 session reseal，不恢复全量明文 descriptor/cache。
3. **函数级 superoperator/fusion（待审批）**：先只融合无异常边界的安全微码短序列；排除 Call/Return、metamethod 和可观察顺序敏感操作。目标是提高轨迹语义提升成本，不是阻止记录。
4. **窄化状态可见面（候选）**：测试按操作族传窄状态视图/专用闭包，避免每 shard 都拿完整 `V/C/E`；评估体积、性能和语义回归。
5. **独立 checksum lane 只防篡改，不防观察**；计时/反 trace 只作辅助信号，注意误报，不作为唯一拒绝机制。
6. **授权 red-team 验收**：量化每构建需观察的 shard 数、实际路径覆盖与语义提升成本；不要以“探针绝不可能取数”为门禁。

漏洞 2 的架构方案仍是候选；本次没有修改 micro-shard 设计。
