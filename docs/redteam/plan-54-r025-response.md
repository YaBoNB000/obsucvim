# R025 对抗研究与防绕过路线图（增量54，2026-09-22）

> R025 报告（攻击方）：载荷 `local a = 9556` 被语句级还原。攻击路径 =
> **运行时锚点注入**（可见层引导代码注入捕获语句）+ 真 Luau 原函数逐层
> 对照解码。本文档做对抗分析并制定稳定加固路线（继承增量53 的稳定性
> 原则 P1-P5）。

## 1. 突破点复盘——真正的缺口在哪

报告第 3 节第 3 步是关键：攻击方在 `local lP=table.concat(cp);`（可见层
引导的 HBOOT 源码装配点）**注入锚点**，捕获了装配好的 HBOOT 容器
（235 B），随后用真 Luau 原函数离线复刻全链（字典层 → D() → 记录流 →
常量池/指令流）。

**为什么注入能成功**：自哈希链（㉚）覆盖的是 HBOOT 源码 + 全部碎片源码，
**可见层引导代码本身不在哈希覆盖范围内**——攻击方修改可见层（加捕获
语句）不触碰 MH 字符串表 ⇒ 哈希链零感知 ⇒ 钥匙流不投毒 ⇒ 程序照常
跑，容器被顺手牵走。这是结构性缺口，不是实现 bug。

**对照**：纯静态还原仍然被挡住（报告自述「靠运行时注入锚点才拿到 w」）
——两段式 loadstring、C 函数身份门、自哈希、假键抵消对静态攻击仍有效。

## 3. 本期实施（增量54，纯编译期，零新运行期路径）

### 54-A 操作数流偏置（建议1）
五流（W/SA/SB/SC/SD）各加每构建随机偏置 `B_w..B_d`（0..65535）：
- 编码：`bx = (v + B_s + st%65536) % 65536`
- 解码：`t = (x - st%65536 - B_s) % 65536`（Lua % 非负，值域不变）
效果：解码后的明文流值分布全面均匀化——「负值只出现在某一流」这类
统计判据失效，自动化流分类器（识别寄存器/常量/偏移角色）必须逐指令
语义分析。处理器语义与操作数值完全不变（偏置两侧抵消）。

### 54-B 双向校验和（建议5）
原型校验和从单累计 `Σv` 升级为双累计：
- `ck1 = Σv`（原有）
- `ck2 = Σ(pos·v)`（位置加权，pos = 流内全局操作数序号）
OS 表双值烘焙，BSS 校验双值同时匹配，任一失配 ⇒ PB 投毒。单向求和
可被重编码器廉价伪造；位置加权累计使伪造必须逐位精确。

### 稳定性论证（P1-P5 逐条）
- P1：全部整数算术，编解码镜像在模运算下恒等 ✓
- P2：零新环境探针（本期改动不触碰 51 守卫与钥匙流环境因子）✓
- P3：失败形态不变（错钥=垃圾，校验失配=PB 投毒，均静默）✓
- P4：本期为默认管线改动（非开关门控）——影响面 = 全部绑定/非绑定
  产物的编码数据与 BSS 校验代码；**可见层结构不变**（改动全在加密
  碎片内部），结构指纹应不受影响（实测验证）✓
- P5：全矩阵 + 指纹 + 审计 + 钥匙扫描本地可验 ✓

## 4. 下期路线（按优先级）

### 阶段二：可见层锚点封堵（可行性已探针，2026-09-23）
**原设想**：引导期取主块自身源码做折叠揉进钥匙流（自覆盖哈希）。
**探针实测结论（此路不通）**：Luau 的 `debug.info(fn, "s")` 返回的是
**块名**（`[string "path"]`）而非源码体——运行时无法取到自身源码体，
自覆盖哈希没有取源面，原设想不可行。
**修正方向（真正封堵锚点注入的路线）**：攻击面不是「代码被改」而是
「装配点可读」——R025 的锚点插在可见层 `HB = table.concat(MH)` 处，被动
读取装配好的 HBOOT 容器。被动观测无法被被观测代码感知（物理上），封堵
只能靠**缩小/隐藏装配面**：
- **已实施（增量55）**：concat+loadstring 收进 PCAL 闭包作用域（boot 级
  不再有具名 `HB`/concat 语句）+ HBOOT 调用后 `MH`/`HB` 即焚——装配面
  从「可见层具名语句」收窄为「闭包内一次性表达式 + 阅后即焚」。
- **彻底封堵（后续大工程，诚实标注）**：`MH` 字节表仍由 metavm 在可见
  层重建（`MH[i] = CHAR(MM[..])`）——真正的锚点。彻底封堵需在 metavm 与
  HBOOT 之间加**新的加密层**（metavm 产物直接进下一层解密，不落可见
  表），属架构级改动，单独立项。
- **R004 边界**：即使装配面全隐藏，真执行器内的活体插桩（钩 loadstring/
  metavm 执行）仍可观测——物理极限不变，目标是成本阶梯。

### 阶段二 L2 层工程勘探结论（2026-09-23，已试制并回退）

对「metavm→HBOOT 新增加密层」做了试制（L2 装载器：metavm 输出不再是
HBOOT 源，而是一个装载器，HBOOT 源二次加密成 blob 藏入其中，运行时解码
并注入 HB 参数）。试制暴露三个硬约束，已回退，存档如下：
1. **体积爆炸 ~×4**：blob 是任意字节，承载进装载器只能用 `\ddd` 转义串
   （每字节 ~4 字符），再经元掩码落表又放大一层。`print(1+2)` 产物从
   ~50KB 涨到 236KB。体积是混淆器的硬指标，×4 不可接受。
2. **局部寄存器超限**：元掩码产物按 170 字节/块落成 `MB1..MBn` 局部，
   体积 ×4 后块数破千，撞 Luau 单函数 200 局部上限
   （`Out of local registers`）。需同时改分块粒度，牵一发动全身。
3. **加层自指悖论**：任何「新增解密层」都需要一个额外的解锁步骤，该步骤
   要么可见（成为新锚点，没解决问题），要么藏进 HBOOT 内（但 HBOOT 要先
   被加载才能运行，自指循环）。**加层无法无代价地消除锚点**——这是结构
   性的，不是实现细节。
**结论**：彻底封堵锚点注入没有「便宜」的方案；可行方向只有两条，均需专项
设计：① 接受体积代价、用更紧凑的 blob 承载（如复用现有 base-94 载体）+
放大分块粒度，把 ×4 压回可接受区间；② 换思路——不藏装配点，转而让捕获到
的容器**离开运行环境即失效**（绑定运行期值，但受 52 教训约束，须用已实证
探针）。两者都列为后续专项，不再本轮仓促实施。

## 5. 诚实边界

- 运行时锚点注入的完全防御 = 让攻击方无法在可见层插入语句而不被感知
  ——阶段二把感知面从「碎片源码」扩到「整个可见块」，但 debug.info 取源
  本身是可钩面：攻击方可以同时改源码 + 伪造折叠（成本 = 理解并复刻
  引导钥匙派生，即攻破 51 守卫同级工作量）。
- 活体全观测（逐帧抓寄存器/常量）仍是物理极限（R004）——加固目标是
  让「拿到一次容器 = 拿到全部」不再成立，把攻击从「注入一个锚点」抬到
  「逐层复刻派生链」。
- 攻击方已展示的解码工具链（decompile_r25.py）在本期加固后失效面：
  流统计判据（54-A）+ 校验和伪造（54-B）；容器捕获路径待阶段二封堵。
