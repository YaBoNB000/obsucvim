# R062：AST 字符串封存原型

> 状态：实验性；用户决定 VM 管线默认开启，`--no-vm-seal-strings` 可关闭。不宣称能抵抗完整动态跟踪。

## 目标与数据流

测试朋友建议的“编译前改写 AST 字符串，使常量池保存密文”思路：

```text
源码字符串字面量
  → AST 内部 SealedStr 标记
  → VM 常量池保存逐字节密文
  → LoadStr 使用点解码到目标寄存器
```

这不是把原始源码放进 VM，也不是运行时重建源码。它只把原始字符串值从 VM 常量池移到使用点解码。运行时寄存器中仍会出现明文。

## 实现

- CLI：VM 构建默认封存；`--no-vm-seal-strings` 可关闭，`--vm-seal-strings` 可显式开启。非 VM preset 默认不封存；显式开启但没有 VM 时会报错。
- 在源码 AST 完成符号解析后、VM 编译前，递归标记非空 `Str` / `LongStr` 节点；不改编译器生成的全局名、点成员名等非字面量字符串。
- 每个字面量有独立 seed/step。构建端只把密文放入 `Const::Str`，发出 `LoadStr(dst, const, seed, step)`。
- 常量池现有 at-rest 加密仍保留；运行期 CDEC 缓存密文，LoadStr 只把明文写入目标寄存器，不回写常量池。
- 只有实际产物含 LoadStr 时才把实验 handler 加进生成解释器；未启用/没有非空字面量时不发射该 handler。
- 使用独立、domain-separated PRNG，避免开关扰动 VM 的既有布局/噪声随机序列。
- `LoadStr` 使用的滚动变换是可逆的混淆，不是密码学加密；seed/step 位于本地客户端字节码中，完整静态分析可恢复。

## 顺带修复：短字符串残留

旧 `LoadK → MkStr` 路径先将字符串加入常量数组，随后只改写指令，却没有删掉失去引用的短字符串常量。现在会在改写后检查常量引用、删除未使用的候选项并重映射仍存活的常量索引；若同一条目仍被全局名等指令使用则保留。新增单测覆盖“删除 `suda` 残留、保留共享键常量”。

## 验收与当前观察

- `cargo test`：32 passed，0 failed，1 ignored。新增 white-box proto/const 解码测试，确认已封存字符串在解开外层 blob 与常量流后仍为密文。
- 完整既有矩阵：`run_tests` 169/169、presets 370/370、multiseed FAIL=0；H2/H3/H4/H5/H6/H7/H8/H5-P0/R061 与防御审计均通过。防御指纹样本使用 seed 772（固定随机结构样本仍须 32/32），以适配默认 LoadStr handler 与短常量清理后的随机输出；测试仍检查既有阈值，没有放宽门槛。
- 新增 `tests/r062_string_seal_experiment.sh`：legacy 与 v15 均通过 Luau 语法、运行结果等价，唯一 canary 不以明文出现在产物中；非 VM 模式正确拒绝该选项。
- 粗略性能观察（同 seed、同一段 26 字节字符串在循环中加载 2000 次，7 次进程运行取中位数）：legacy 约 87.16→90.66 ms（+4.0%），v15 约 177.14→218.04 ms（+23.1%）；样本产物 legacy 约 +3.9%，v15 约 +9.4%。这是单机微基准，不代表所有程序。解码不缓存明文，成本随字节长度和访问次数增长；重复热字符串尤其昂贵。

## 安全边界与限制

1. 这只证明输出中没有直接明文 canary，并不证明完整解码后的常量/指令结构仍不可恢复。
2. `LoadStr` 的 seed/step 与算法都在客户端；一旦攻击者恢复该操作语义，可以离线批量解密。
3. 解码后的值必须在运行时寄存器出现；动态跟踪可截获。
4. 本阶段只封存源码字面量；全局/成员标识符和 VM 自身字符串仍走原有路径，不能据此说“整个常量池只有密文”。
5. 因性能和静态可恢复边界，不能宣传“字符串不可破解”；VM 默认开启是用户的产品开关决定，非 VM 模式不受影响，可用 `--no-vm-seal-strings` 回退。
