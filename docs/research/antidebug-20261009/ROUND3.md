# 第三轮：C5 路径历史绑定的块窗口自重封

**日期：2026-10-09。范围：继续自研研究；仅新增本目录研究工件，现役引擎零改动。**

## 结论

C5 是三轮研究里**第一个有正确变体存活下来的候选**：V3 设计在独立模型（Python + Luau）中通过了全部合法性实验，并复现了预期的攻击反例与诚实边界。但按入选门槛，它**仍未入选**——"不倒退"需要引擎内原型 + 全矩阵 + 性能/内存实测才能判断，本轮不允许改引擎。

## 1. 动机与查重

R064 的诚实边界是：同进程 trace 是客户端极限，而**转储/重放**是比 trace 更便宜的一档攻击。现役块钥匙 = 位置 + 会话盐 + 每运行 SALT：静态文件无运行盐解不了，但**同一次运行内**，拿到密文加当时状态的快照可以离线解；块与块之间没有"必须按实际执行路径走"的约束。

真 Luraph v15 的"常量池与指令流随执行演化"（红队报告）是其四表/状态机机制的副产品；我方未实现任何路径历史绑定的解码（adoption inventory 的 A1 是四表派发，另一回事；HANDOFF 后续清单里的 per-shard checksum lane / boot-state indices 也不同）。**判定：仓库内没有此机制，算新候选。**

## 2. 设计演进（每步都被实验否证或收窄）

### V1（直觉设计）：入口钥匙 = f(存储钥匙, 当前路径 digest)

**反例（Python 模型复现）**：digest 在"上次编码"与"下次解码"之间必然移动（哪怕只有本块自己的 ops），**单帧顺序重入都解出垃圾**。`v1_sequential_revisit_corrupts = 1`。该设计直接死刑。

### V2（退一步）：字面滚动钥匙 + 共享密文库

正确性没问题（顺序/交错全稳），但 **(密文, 当前钥匙) 二元组就是完整能力**——不跟随路径、跨帧复制、乱序单块 oracle 全部成功。`v2_pair_copy_oracle_succeeds = 1`。这只是 C4 在块粒度的翻版：访问次数绑定，不是路径绑定，**不算达标**。

### V3（结构结论）：每帧密文副本 + 每帧链 (digest, 帧秘密)

V1 和 V2 合起来给出一个结构性结论：**共享密文库与"每帧路径绑定"矛盾**（密文的钥匙只能是最后那个编码者的历史）。因此路径绑定必须配每帧密文副本：

- 首触：从母本按构建钥匙解出（与今天同保护级）；
- 每次退出：`chain_b = fold(chain_b, digest, secret_E)`，用新链重编码回**本帧**副本；
- 每次进入：`key = fold(chain_b, secret_E)` 重算——解码钥匙同时依赖路径历史与帧身份（表地址类秘密，每帧每运行不同）。

## 3. 实验结果

### 合法语义（必须全过）

| 场景 | Python | Luau |
|---|---|---|
| 循环重入同块（链演进下明文稳定） | ✅ | ✅ |
| 嵌套/多块交错路径 | ✅ | — |
| 双协程同原型交错（独立帧） | — | ✅（2 协程 × 40 次 yield） |
| 递归（每层新帧） | ✅（16 层） | — |

### 攻击与边界（按预期复现）

| 场景 | 结果 |
|---|---|
| 陈旧密文重放（旧访问的密文 + 当前链） | ❌ 垃圾（拒绝）✅ |
| 跨帧二元组复制（密文+链，无帧秘密） | ❌ 垃圾（拒绝）✅ |
| 全状态复制（密文+链+秘密） | ✅ 可解——R004 物理极限，如实记录 |
| 未触达块的静态母本 | 与今天完全同级——**首访前无路径绑定** |

### 代价测量（Luau，本轮独占 CPU，无后台干扰）

热循环模型（3 块 × 20,000 迭代 × 5 通道 × 32 字，含相同"执行"工作量）：

- 现役形态（解码一次 + 每访问原地重掩码，H4-6B 同类）中位耗时 0.268s；
- C5 候选（每访问解密 + 重编码 + 链更新）中位 0.446s；
- **中位比值 1.667×**（9 轮交替测量，范围 1.47–1.86）。

这是**块窗口工作量的比值，不是整个 VM 的开销**；真实占比要等引擎内原型。内存代价未实测：每帧副本 ≈ 帧数 × 触达块 × 5 × 32 字（估算，非测量）。

## 4. 与现役机制的冲突点（原型前必须解决）

1. **H4-6A 块缓存（E.bch，cap 0..2）存的是解码态窗口**——今天全状态 dump 本来就能从缓存拿明文。C5 若要兑现"密文快照不可解"，缓存必须改存重编码密文（每次访问都解 = 已含在 1.667× 里）或明确接受缓存暴露面不变。
2. MZD/CHQ 投毒通道需要折进链更新，否则删 Nop 的攻击面回归。
3. 帧秘密来源建议复用 SALT 的表地址折叠族（每帧每运行不同、整数精确、P1 合规），不发明新探针。
4. bdec 的 per-visit 重掩码路径与重编码路径二选一，不能叠加付两遍成本。

## 5. 诚实评估

- **收益**：单点密文快照（不含全状态）不可解；跨帧/跨运行/乱序重放全部垃圾；热块（循环体）的取证必须跟随执行链。
- **边界**：首访块无路径绑定；全状态观察者不受影响（R004）；帧副本内存代价；1.67× 块窗口开销。
- **判定**：方向成立、正确变体存在、代价可量化——是三轮里最接近入选的候选。但"不倒退"未证明（需引擎内原型走完整强制工作流），**本轮不加入，不宣称强度提升**。


## 7. 第二轮补充测试（同日，继续测试）

### 7.1 热块规模的链值碰撞（改写第 3 节的一个结论）

对 V3 链做 500,000 次访问扫描（3 个种子）：**碰撞 58/60/66 次，与生日解析式 58.2 吻合，最早出现在第 ~21,440 步**。结论修正：V3 的"陈旧密文重放必拒"在热循环规模下退化为概率性——R064 级热点（数十万次访问）必然出现钥匙碰撞，碰撞发生时旧快照重新变得可解。

两个修复变体的实测：

- **计数器揉进钥匙**：按块碰撞 44/59/50 次——**修不了**。我原先"构造性唯一"的判断是错的（模 2^28 内计数器不改变生日空间），实验把它抓了出来。第一版扫描还有跨块混算缺陷（跨块同钥不构成重放能力），已修正为按块统计。
- **访问计数标签**（tag = fold(chain, secret, count)，随密文一起存、每次重编码时更新）：钥匙碰撞依旧出现（14/23/23 次/300k），但**陈旧重放接受 = 0/0/0**。代价是每 (帧, 块) 多存一个标签字段并多一次折叠。这是当前推荐形态。

### 7.2 部分观察攻击者的量化

攻击者一次读全帧状态 + 事后快照密文，按观察到的路径事件模拟链演进：

| 路径观察比例 | 可解块数 |
|---|---|
| 100% | 12/12（全观察者赢，R004 边界） |
| 99.9% | 0/12 |
| ≤99% | 0/12 |

漏看**一个**路径事件就污染后续全部链预测。诚实保留：模型里的事件值不可猜；真实 digest 输入（块号/指令数据）部分可预测，真实余量会小于此表。

### 7.3 生命周期与工程缺陷（模型层发现并修复，非产线）

1. **中断幂等缺陷**：`touched` 标记原在解码前置位——执行中出错/让出后重试会用错钥匙。已改为"重编码成功后才置位"，`pcall` 中断重访、yield 中断续跑、`coroutine.close` 弃帧后全部验证通过。
2. **测试采样缺陷（自踩产线已知坑）**：协程调度器用 `pick() % 32` 采样，Park-Miller 流低 5 比特周期仅 4（48271≡15 mod 32，x→15x+11 周期 4），28 个协程永远调度不到、调度器死循环。这正是 `rng.rs` 注释警告过的低比特短周期坑；改为全值乘法约简（与产线同纪律）后 1,952 次 resume 0.58ms 完成。研究脚本能踩中，说明该纪律不是过度设计。

### 7.4 Luau 压力与开销缩放

错误/取消/close/他帧隔离/母本不可变/32 协程随机调度 9 项全过。开销按块尺寸缩放（候选/基线中位比，9 轮）：

| 块字数 | 中位比 | 范围 |
|---|---:|---|
| 8 | 1.394× | 1.24–1.44 |
| 32 | 1.416× | 1.35–1.48 |
| 128 | 1.412× | 1.34–1.46 |

线性、无尺寸放大；与第 3 节 1.667×（不同循环形态）合并口径：**块窗口开销约 1.4–1.7×**。内存代价（帧 × 触达块）仍未实测。

### 7.5 更新后的判定

C5 = V3 + 访问计数标签形态通过第二轮证伪。原型前遗留：标签在帧内的存放布局、digest 输入可预测性的真实余量、与 H4-6A 缓存的交互（第 4 节未变）、内存实测。**仍未入选，不改引擎。**
