# 红队战役战略：真破 Luraph v15（2026-09-25 立项）

## 背景与目标
前两轮侦察（`docs/redteam-luraph15-recon.md` 结构测绘、
`docs/redteam-luraph15-deep-recon.md` 试解）停在 CPS 墙前，结论是
「工程繁琐墙、非密码学墙」。本轮目标：**真的把它解开**——还原出被保护
的原始程序，并把过程中每一堵墙、每一次碰壁如实记录；顺带把它的全部防御、
隐藏手法、防绕设计、整体架构挖出来学习。

纪律：
1. 一切结论必须来自实测（运行/字节/日志），不引用旧报告的推断当结论。
2. 碰壁即记录：失败的方法、报错原文、为什么不行，和成功同等重要。
3. 样本本体不改动；所有改动走「源码补丁 + 仪表化」副本。
4. 不吹「我们更强」——只记「它有什么、怎么做的、我们有没有、差在哪」。

## 阶段划分

### 阶段 A：破环境墙（墙#1 环境绑定 + 墙#2 只读全局）
旧侦察结论：CLI 里 `_G` 只读、桩不进去；`Vector3.new` 等缺失；
`task.*` 运行期拼名访问。
- A1 源补丁**局部遮蔽**（不碰 `_G`）：文件顶端注入
  `local Vector3/vector/task/... = 万能桩`，用元表自动生长
  （__index 生桩、__call 返桩、算术元方法返桩）吸收一切未知访问。
- A2 遮蔽 `getfenv`，返回桩环境，让运行期拼名索引有对象可落。
- A3 逐错误迭代：跑 → 报错 → 定位缺什么 → 补桩 → 再跑。每次碰壁记录。
- 出口判据：模块表构造成功、引导段开始解码（或明确死于别处）。

### 阶段 B：破 CPS 墙（墙#3 分散解码）
不解 150 个微 handler 的逻辑，改走**动态旁路**：
- B1 截获模块表构造结果，把所有原语槽（数字键函数）包上日志壳。
- B2 重点壳 `buffer.writeu8/readu8/fromstring/tostring`：CPS 解码的最终
  产物必经 buffer——**旁路重建解码后缓冲**，不需要理解状态机。
- B3 壳 `pcall/xpcall/setfenv/getfenv/coroutine.*`：看运行时防御到底
  有没有、藏在哪（旧报告说「无运行时防御」——用调用日志实证复核）。
- B4 找到解释器主循环（`[18]`），注入指令级 tap：dump 每条 VM 指令
  的 opcode/操作数，重建执行轨迹。
- 出口判据：拿到解码后的程序缓冲 + 指令流。

### 阶段 C：还原程序（真正破开）
- C1 解析解码后缓冲的序列化格式（对照解释器源码逆推）。
- C2 写反汇编器/反编译器，还原出被保护的原始程序。
- C3 与原样本头部水印/已知信息对照验证正确性。
- 出口判据：产出可读的还原源码或等价指令序列，行为解释完整。

### 阶段 D：防御/隐藏/架构总集
- D1 防御全集清单：逐条「机制—位置—强度—我方对照」。
- D2 隐藏手法清单：命名体系、调度形态、常量藏法、拼名表。
- D3 架构解剖：分层图 + 数据流 + 信任边界。
- D4 全部碰壁记录汇编（含本轮新增）。
- 产出：`docs/redteam-luraph15-breakout.md`（总报告）+ `redteam/` 工具。
