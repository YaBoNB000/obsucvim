# 防环境记录器实施方案（C6-IMPL v1）

**日期：2026-10-11。状态：已废弃（同日用户决策改用 WTF-PORT 路线，见 `WTF-PORT-PLAN.md`）。本文档保留归档；其 L1 反录制重放能力未实施，重启需重走审批。**
**依据：ROUND4/ROUND5 两轮证伪实验 + 现役工具搜索调研 + c6b/c6c 实测数据。**

---

## 0. 一页结论

新增一个**默认可开的核心库认证层（CORE-ATTEST）**：启动期用每运行新生的 nonce 向环境发起少量 bit32 查询（确定性混入边界输入类），用 VM 内纯算术镜像本地复算，**以代数差值 lane（无分支）折叠进会话钥匙**——录制重放工具与错误移植的沙箱因答不上新颖查询而静默死亡。实测成本 8.6µs/启动，运行期零开销；不绑定目标环境（任何正确 Luau 都能跑），因此可与现有 exguard（API 层，绑定态）分层互补。

**它不是墙**：自带真 Luau 的工具和正确实现照常通过（它们的判别面在仿造 API 层——exguard 的领域）。本方案的贡献是把"防环境记录器"从**零**（默认管线目前无任何环境认证）抬到"必须用正确 Luau 才能跑"。

## 1. 威胁模型与分层（结论固定，不再重研究）

| 层 | 攻击者 | 现状 | 归属 |
|---|---|---|---|
| L0 | load/字符串表/时钟等 env 级钩子 | **已被杀**（反挂钩闸、原生元表捕获、GFE(0) 时钟路径，实测） | 已有 |
| L1 | **纯录制重放 / 错误移植沙箱** | **当前为零防护**（默认管线无环境认证；常量探针录一次全过） | **本方案** |
| L2 | 真 Luau + 仿造 Roblox/executor 层（现役主流工具形态） | exguard（绑定态）对抗其仿造层 | 已有（bind 模式） |
| L3 | 跨运行快照重放 | SALT 已有；C5 候选增强 | 已有/研究 |
| L4 | 同进程全状态插桩 | R004 物理边界 | 不可防 |

搜索确认（ROUND5 §1）：现役工具自带真 Luau 二进制 + executor 档案 + HTTP 重放，2,643/2,645 真实样本可自动路由。L1 与 L2 是不同攻击者，**不能用同一机制对付**。

## 3. 机制规格（CORE-ATTEST）

### 3.1 探针族（首轮 3 个，全部 ROUND5 实测背书）

| # | 环境调用 | 镜像（VM 内纯算术） | 杀死对象 |
|---|---|---|---|
| P1 | `bit32.bxor(x, y)` | 32 轮双输入位循环 | 录制重放（nonce 无录制）|
| P2 | `bit32.band(x, y)` | 32 轮与循环 | 同上 + 交叉验证 |
| P3 | `bit32.bnot(x)` | `4294967295 - canon(x)` | 单目规则错误 |

**语义契约**（ROUND5 §3.1 实测）：参数向零截断后 mod 2³²，inf/NaN→0。镜像 200k 扫描 0 失配。

### 3.2 nonce 变换（确定性边界类混入——保证已知错误规则必撞）

```text
x = (SALT_fold % 2³²) − 0.5          ← 负/正分数类：floor 风格移植必死
y = ((SALT_fold × 48271) % 2³²) + 2³² ← 越界类：clamp 风格移植必死
```

每个探针至少覆盖一个判别类 ⇒ 对已知错误规则检测率 = 1（非概率式）。新增错误规则类时扩充变换表即可。

### 3.3 折叠设计（R061 教训：无分支、无 oracle）

```text
diff = (env_answer − mirror_answer) % 2³²     ← 干净环境恒 0
session_key = (base_key + diff × lane_coef) % 2²⁸   ← 代数 lane，无可删分支
```

- 错误答案 ⇒ 非零 diff ⇒ 钥匙静默漂移 ⇒ 后续解码全垃圾，无错误信号、无固定陷阱位置；
- diff 与既有 MZD 投毒 lane 同族发射，不新增统一 getter；
- 镜像在 VM 内运行期计算（每次启动 8.6µs，c6c 实测），Rust 侧**不需要**预知答案（无镜像对齐风险——这正是 ROUND5 纠正 ROUND4 循环构造错误后的正确形态）。

### 3.4 调用时机与成本

| 项 | 值 |
|---|---|
| 启动期 | 3 探针 + 3 镜像 ≈ **8.6µs**（10 万次启动实测均值） |
| 运行期 | 0（不复检；周期复检留 Phase 3 评估） |
| 体积 | 每构建 +200~400B（探针与镜像发射，估） |

### 3.5 开关

- Phase 1：`--attest-corelib`（opt-in）；**关闭时与现役产物逐字节一致**（P4 硬门槛）；
- Phase 2：默认开启（条件见 §5）。

## 5. 分阶段实施与验收

### Phase 0 —— 预研门（不动引擎，产出放行条件）

- [ ] 真机清单：Roblox Luau + 至少 2 个主流 executor 实测 bit32 截断规则与 CLI 一致（30 分钟脚本，用户侧执行；**这是唯一无法本地代验的 P2 项**）；
- [ ] 复核 Luau 0.735→当前 Roblox 版本 bit32 无语义变更（changelog）。

### Phase 1 —— 引擎原型（flag 门控）

- [ ] template.rs：boot 期探针+镜像+diff lane 发射（av_fold 同族形态）；
- [ ] manifest 键 + key_literal_check 通过；
- [ ] Rust 单测：镜像恒等式边界类扫掠（移植 c6b 的 200k 扫描为 release 模式测试）；
- [ ] 新增 `tests/corelib_attest_test.sh`：
  - A. 干净运行等价（开/关对比，全语料）；
  - B. **绞杀测试**：录制运行 A 的全部环境应答→在重放沙箱跑运行 B 产物→必须静默垃圾且无错误特征（移植 c6b 4b 为产物级测试）；
  - C. floor/clamp 错误移植沙箱→必须死（移植 c6b 4c）；
  - D. 开关关闭与 HEAD 产物逐字节一致；
- [ ] 全矩阵：cargo / run_tests / presets / multiseed / H 系列 / D 系列 / S1–S5 / 示例重生成；
- [ ] 文档四处同步 + 提交推送。

### Phase 2 —— 默认开启（放行条件全部满足才启动）

- [ ] Phase 0 真机清单全绿；
- [ ] Phase 1 全矩阵绿 + 绞杀测试稳定（多 seed）；
- [ ] 误报账本为零（含协程/错误路径/变体环境模拟）；
- [ ] 默认翻转后全矩阵重跑 + 示例重生成 + 文档同步。

### Phase 3 —— 与 exguard 联动（绑定态增强）

- [ ] CORE-ATTEST（核心库）+ exguard（API/executor）双层叠加，绑定态产物同时具备 L1+L2；
- [ ] 评估周期复检（轻档，exguard 已有节律框架）是否值得运行期成本；
- [ ] C5（路径绑定重封）若立项，diff lane 与其链路统一设计。

## 7. 诚实边界声明（对外口径模板）

> 本机制使混淆产物无法在"录制的环境应答表"或"语义不正确的模拟环境"中运行，迫使分析工具使用语义正确的 Luau 运行时。它不检测调试器，不阻止同进程插桩与全状态观察，不构成对正确实现的对抗。环境绑定能力由绑定模式（exguard）另行提供。
