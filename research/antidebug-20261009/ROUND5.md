# 第五轮：C6 第二轮——搜索发现 + 新颖查询/本地镜像一致性实证

**日期：2026-10-11。范围：研究；零产线改动（修复提交 871c9c3 之后的工作树）。**

## 1. 搜索发现：现役环境记录器/仿真器的真实形态

公开工具（Deobfuscator-Luraph-V15 及其衍生，2,645 个真实样本 2,643 个可路由）的实际架构：

- **真 Luau 运行时 + 仿造环境层**：脚本在一个真的 Luau 里执行——`bit32`/`string`/`math` 是真实现；仿造的是 Roblox/executor 面（services、Vector3、CFrame、UDim2、UI 库、getgenv/checkcaller/identifyexecutor，甚至 executor 档案切换）；
- **录制 + 重放混合**：envlog 记录查询，HTTP 响应可重放；
- **反篡改陷阱隔离**：识别 LPH_CRASH 类陷阱后禁用该路径沿稳定分支重跑——我们 R061 把 Ou/De 改成无条件双代数 lane 正是针对这种"删分支"式绕过的设计；
- 沙箱里未触发路径的常量靠活动 VM 逐个解密（与我们 R064 白盒测量同族）。

**对我们防线的含义**：核心库语义探针挡不住这类工具（它们用真 Luau 答题）；它们的弱点在**仿造的 API 层**——那是 exguard（51）的领域、也是 52 号误报雷区。防记录器的现实分层：杀纯录制重放（便宜、稳）→ 杀错误移植（中等）→ 无法杀正确实现（边界）。

## 2. 本轮新机制实证：新颖 nonce 查询 + 本地镜像 + 静默钥匙折叠

上一轮已证伪"nonce 答案折进钥匙做认证"（循环构造）。本轮的正确形态：

```text
x, y = nonce 变换（可含边界类）          ← 每运行新生
answer = env.bit32.bxor(x, y)           ← 唯一环境查询，录制件不含本次答案
mirror = VM 内纯算术 xor(x, y)           ← 本地计算，不经环境、无法用环境假答对冲
answer ≠ mirror ⇒ 错钥静默死亡            ← 无 oracle，攻击者不知道哪个探针死了
```

与双路都取自环境的方案（上一轮）不同：镜像在本地，"同值假环境"没有第二个可伪造的入口——该攻击面直接消失。

## 3. 实测结果（真 Luau 0.735 CLI，`c6b_local_mirror.luau`）

### 3.1 真 Luau bit32 语义测绘（16 个边界类）

规则：**参数向零截断，再 mod 2³²**；inf/NaN → 0。关键判别类：

| 输入 | 真 Luau | 错误移植常见行为 |
|---|---|---|
| `-0.5` | → 0 | floor 风格 → -1 → 0xFFFFFFFF（**发散**） |
| `2³²+n` | → n | clamp 风格 → 0（**发散**） |
| `-1` | → 0xFFFFFFFF | clamp → 0（**发散**） |
| `0.5` | → 0 | 一致 |
| JS ToInt32 | 向零截断+回绕 | **与 Luau 完全一致（正确规则）** |

### 3.2 镜像精确性（误报面）

本地镜像（纯 double 精确算术）对真运行时做 **200,000 对**扫描，覆盖 8 个输入类（全 u32 域、负数、分数、负分数、2³² 上溢、2⁵³ 前沿、符号边界）：**0 失配**。P1（整数精确镜像）在测绘域内成立。

### 3.3 攻击矩阵

| 攻击者 | 结果 |
|---|---|
| 精确重放（录制表答任意查询） | **死于新颖 nonce**（录制件没有本次答案） |
| floor 风格错误移植 | **死于负分数边界类** |
| clamp 风格错误移植 | **死于越界/负数边界类** |
| 正确截断规则（JS ToInt32 型） | **存活**——它就是对的，这是诚实边界 |
| 自带真 Luau 的工具（搜索发现的主流形态） | 存活（核心库面无判别力，判别面在 API 层） |

附记（方法论）：本轮实验自身踩了两个坑并被结果抓出——Lua `%` 对负数非负导致我的"js 规则"实现实际是 floor（修正后才是真截断）；这再次说明**镜像/仿真规则必须实测，不能凭记忆写**。

## 4. 若要实施（设计约束，未实施）

- 接入点：CDEC 钥匙折叠 lane（CENVPROBE 同族形态），nonce 源复用 SALT 地址折叠（每运行新生、P1 合规），镜像用 VM 内既有纯算术原语；

- P2 门槛（本轮无法本地验证）：真实 executor 的 bit32 行为必须与 CLI 一致后才能上钥匙流——这是 51 的老规矩；

## 5. 判定

C6 两轮后的最终结论：**防环境记录器的可实施增量 = 新颖查询/本地镜像探针（本轮实证）+ 现有 exguard API 层认证**；前者杀低端重放工具，后者对抗沙箱模型，两者都不设墙。本轮不实施；若批准，按上述约束走引擎原型 + 强制工作流。
