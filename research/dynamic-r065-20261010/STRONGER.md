# 更强的动态攻击：改装运行时白盒实测（第二轮）

**日期：2026-10-11。对象：未修改的 R065 / R064 产物（哈希复核一致）。零产线改动。**

第一轮证明了原版 Luau 运行时上的动态方法全部失效。本轮升级到公开工具实际依赖的层级：**攻击者自带的改装运行时**。我们自建了一个白盒研究版 Luau CLI（`work/luau-wb/`，补丁存档于 [`whitebox-runtime.patch`](whitebox-runtime.patch)，环境变量门控、不设变量时行为与原版一致）：

- 在**字符串驻留必经点**（`luaS_newlstr` 查找或创建 + `luaS_buffinish` 缓冲拼接）下金丝雀钩子——任何被物化的 Lua 字符串都会过闸；
- 运行时级**冻结 `os.clock`**（直接补 C 函数，不是环境层假装）；
- 周期性**重度自旋**模拟重型插桩开销。

## 结果矩阵

| 实验 | 结果 |
|---|---|
| R065 + 金丝雀钩子 | **命中**：`bysuda` 于第 3,361 个驻留字符串处被截获，恰好 1 次（惰性解码、单次使用）；程序照常完成，stdout/退出码与干净运行一致，全程 30ms |
| R065 + 冻结时钟 | 同样命中并正常完成——**计时守卫在运行时层攻击者面前被中和**（时钟经 `GFE(0)` 真 `_G` 走 C 函数，攻击者补掉即失效） |
| R065 + 重度插桩 | 正常完成（载荷太小，128 迭代窗口可能都没凑满） |
| R064（7KB 真靶）+ 钩子（用到的常量 `R064_7KB`） | **命中**：第 469,128 / 共 514,646 个字符串处截获，恰好 1 次；stdout 与干净运行逐字节一致，1.08s |
| R064 + 钩子（**未执行到的**错误分支串 `roundtrip mismatch`） | **0 命中**——惰性常量解码使未走到的路径永不物化，运行时级字符串钩子也看不见 |
| R064 + 重度均匀插桩（+6% 耗时） | 正常完成，stdout 一致，**守卫未触发**——自适应基线按设计吸收均匀开销；守卫瞄准的是中途起跳式/非均匀减速（D12 审计形态），且冻结时钟可直接中和 |

附带发现（诚实记录）：明文源码 `local a = "bysuda"` 直跑时金丝雀 **0 命中**——原版 Luau 编译器把未使用的局部赋值死码消除，字符串根本不驻留；**我们的 VM 忠实执行死存储**，物化窗口照样存在。这是保真度差异，不是漏洞，但攻击面意义上：死代码里的秘密在原版里不出现、在我们的产物里会出现。

## 结论

1. **R004 物理边界在两个靶上都被具体量化**：同进程运行时插桩可以截获任何被程序实际物化的秘密——R065 一次命中、R064 一次命中，开销可忽略。这不是失守，是一贯文档化的边界，本轮给了它精确的数字。
2. **真正起作用的对抗面**（按实测）：
   - **物化次数**：R064 的 superoperator 融合把解码记录从 929,567 压到 412,706（-55.6%）——每次物化都是攻击者的一个闸口事件，压缩物化次数直接压缩可截获面；
   - **惰性解码**：未执行路径的常量（`roundtrip mismatch`）对运行时钩子**不可见**——攻击者必须先获得路径覆盖；
   - **计时守卫**：对均匀开销无效（设计如此）、被时钟控制者中和——它是针对特定 tracer 形态的档位，不是墙，文档口径应继续保持这一点。
3. 研究阶段的 C5（路径历史绑定重封）正是针对本轮验证的"快照+重放"成本：它不阻止截获，但让"跟一次运行"以外的重放贬值。
