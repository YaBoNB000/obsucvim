## 修复清单（engine-server.mjs，本轮全部落地并复测）

1. 限流按 socket 地址，不信任 XFF（防伪造绕过）
2. 旧 `/api/health` 当时加限流与版本缓存；该诊断端点已于 2026-10-21 删除
3. 引擎并发信号量 ≤4，超出 503（防资源耗尽）
4. 超限 body 回 413 后再断（防空 500 / 半写响应）
5. 临时文件名唯一化（防并发竞争互删）

## 客户端固有边界 → 已修复（2026-10-11 第二轮）

原四项客户端边界**全部移到服务端**（engine-server.mjs，状态持久化 `tools/.state.json`，gitignored）：

| 原边界 | 修复 | 复测 |
|---|---|---|
| 人机验证可 devtools 旁路（历史记录） | 原算式题；2026-10-21 已替换为服务端生成的图片拼图挑战 | 新挑战一题一用、3 分钟过期、答案坐标只在服务器保存；详见下方后续变更 |
| 登录锁定在 localStorage 可清除 | 服务端按邮箱计数（5 次锁 60 秒） | 存在用户错密码 ×5 → LOCKED(60s)；锁定期正确密码仍拒 ✓ |
| 会话无签名可伪造 | 256 位随机令牌（服务端会话表，7 天有效期） | 伪造令牌 → 401；/api/me 恢复会话 ✓ |
| 邮箱验证码 sessionStorage 可读 | 签发/校验/冷却/尝试上限全在服务端；demo 邮件模式下响应携带 demoCode（唯一残留演示通道，`OBSUCVIM_REAL_MAIL=1` 关闭） | 爆破 6 位码 → 5 次 CODE_EXHAUSTED ✓ |
| （新发现）客户端额度可绕过 | 混淆端点要求 Bearer 令牌，额度服务端按账号裁决并递减 | 无令牌 → 401；有令牌 → 200 且 quota.used 递增 ✓ |

附带加固：密码改 **scrypt**（N=16384，timingSafeEqual 比较）；登录对不存在用户做等价哈希比较（防时序枚举）；不存在用户不触发锁定（防恶意锁定他人）；两步注册的昵称/密码存服务端草稿（确认步只带 email+code，防两步间篡改）；认证端点全量进限流桶。

## 结论

第一轮 5 项后端漏洞 + 第二轮 5 项客户端边界全部修复并复测闭合。残留：demo 邮件模式验证码在响应中明示（无邮件外发能力的演示通道）；单节点文件状态（`.state.json`）无并发写保护——多实例部署需换数据库。

## 后续变更（2026-10-21）

- 删除了公开 `GET /api/health` 诊断端点；未知 `/api/*` 路径统一返回 404。SMTP 状态仅在服务启动控制台输出，不通过网页接口公开。
- 前端不再轮询 health，也不再用占位 Mock 伪装混淆结果；服务端不可用时直接显示失败。
- 注册按小写规范化邮箱去重，并在服务端持久化注册 IP 的 HMAC 索引；同一 IP 只能完成一个新账户注册。默认忽略 XFF；仅显式列入 `OBSUCVIM_TRUSTED_PROXY_IPS` 的反向代理可传递 XFF。
- 旧账户注册时没有留存 IP，无法追溯补录；新策略只对更新后完成的注册可验证。
- 人机验证改为服务端生成的 PNG 拼图缺口挑战；答案坐标不下发，服务端一次性校验，3 分钟有效、允许约 5 px 人工误差，并有 700 ms 最短答题时间及认证限流。该方案提升普通脚本绕过成本，但不能阻止高质量图像识别/AI；面向高风险公网场景，Cloudflare Turnstile 或 hCaptcha 这类托管验证通常更强，需要配置站点密钥并由服务端向提供方验证令牌。
