# V16 Keyed-Decode 计划（草案 v1，2026-10-24）

> 立项背景：R067.5 hard 产物被离线静态还原（kkksu 报告，证据链完整）。
> 根因定性：v15 的载荷解码链是**产物字节的纯函数**——所有种子/置换/别名/掩码
> 自描述于产物，验证链只控制「运行权」、不控制「字节可见性」。
> 本计划的目标形态（用户原话）：**非 exec 环境执行，payload 都拿不到**。

## 1. 现状密钥图（要改的接缝）

载荷（用户源码）→ 自研 ISA 二进制（原型/常量）→ 多层封包。产物内自描述的密钥件
（kkksu 报告逐项实证）：五段封包字母表+掩码初值、两阶段字节掩码种子（含前 64 B
密文哈希派生段）、常量块独立状态流种子、操作数置换（如 `[2,1,3,0]`）、操作码别名表、
槽位/字段置换（`slot_perm`/`field_perm`/`block_word_perm`）。

**已有接缝（本次复用，不重造轮子）**：
- 逐函数入口：`local cef = CENVPROBE() local xtok2 = XPROBE(fi)`（template.rs:2650）
- `XTOK` 折叠进 `SLT`（2747），`SLT` 参与逐块解密初始状态
  `st = (PS + fi*PT + s0*fpb + SLT + QF[fi]*CQB + pzb) % 268435456`（2731 世代）
- 但 XTOK/SLT 今天是**确定值**（静态可推）——v16 的全部动作 = 把一个
  「只有合法 exec 运行时才算得出」的量接进同一条链。

## 2. 方案分级

### v16-a · 宿主指纹派生钥（客户端自闭环，不依赖网络）

- 派生：`K_run = fold(闸门动态结果 + 结构布尔向量 + 稳定指纹)`。
  - 动态结果：SCHALL 各闸返回值与转录 ATTEST（今天已算，只是没接进解码链）；
  - 结构布尔：`IsStudio()==false`、`checkcaller()`、`typeof(Vector3.new())=="Vector3"`、
    `tostring(Vector3)` 格式折叠（CENVPROBE 已在算的东西复用）；
  - 稳定指纹：`identifyexecutor()` 的**名字段**（版本号**不混入**——执行器升级不能炸合法用户）。
- 接线：`bdec` 的 `st`、常量块状态流初值、两阶段掩码种子三处各混入 `K_run` 派生项。
- 效果：
  - 裸 Luau/杂牌宿主：闸门拒（R067.4 起精确报缺失），且即便硬绕报错路径，
    `K_run` 不符 → 解出毒字节 → VM 立即崩殂，**无任何可校验对错的神谕**；
  - 静态复现者：必须先 1:1 仿真整套闸门栈（含 debug 深内省语义）才算得出 `K_run`，
    工时从「小时级」抬到「先仿真执行器」级。
- 诚实边界：`K_run` 的值域理论上是确定的——完美仿真者仍可还原。本条抬的是工时，
  不是数学不可能性。

### v16-b · 服务端持钥（强形式；「非 exec 拿不到」的唯一彻底实现）

- 载荷核心常量/字符串块换用**产物内不存在**的密钥 `K_srv`；产物只含密文。
- loader 在 `/licenses/validate` 握手时取回 `K_srv`，绑定：卡密 + HWID + 过期 +
  attest 能力上报（attest.luau 已在 loader 最前置位、数据已在回流——接利用现有轨道）。
- 非 exec / 无网络 / 卡密失效 → `K_srv` 不抵达 → **载荷物理缺席**（V1/V2 的强形式）。
- 代价与风险（写死，不粉饰）：
  - 执行期必须联网；服务不可达 = 脚本停摆；
  - 执行器 HTTP 能力差异（`request`/`http.request`/`syn.request`…）要先出支持矩阵；
  - 缓存窗口策略是取舍：断网容错缓存 N 小时 ⇒ 该窗口内存在一次性 dump 面；
  - 「合法跑过一次后 dump」依旧防不住（与 §0 一致）。
- 服务端影响：发布管线新增「每版本一份 K_srv 托管」（与双产物 variants 对齐），
  老版本产物无钥形态保持向后兼容（loader 按版本路由）。

### v16-c · 轮换加强（可选，a/b 之上叠加）

- `K_run`/`K_srv` 按会话/心跳轮换；多原型分钥（大脚本每个原型子钥不同）。
- dump 者成本再抬（dump 一次只拿到当期分片）。

## 4. 风险登记

1. **fail-closed 面变大**：密钥源任一抖动 = 合法端变毒字节。缓解：只取结构稳定值 +
   GateProbe 先行出 Delta 实测表；上线前灰度种子。
2. **执行器版本更新**：凡混入易变字段（版本串等）即事故温床——设计已排除版本串。
3. **诊断必须同步**：trace 通道与 GateProbe 同步加「密钥派生失败点」编号，否则重演
   R067 时代的盲排。
4. **误伤责任**：v16-b 的可用性坏点会直接传导到终端用户，需要「服务端挂起时的
   明确行为」（一律 fail-closed，不做 fail-open）。

## 7. v16-a 施工细则（拍板后第一轮迭代，2026-10-24）

拍板：先 a、只保 Delta、不走 b。据此 v16-a 的构造定稿为**「转录绑定解码钥」**：

1. **原理**：纯客户端确定性方案无法引入真随机熵（攻击者可离线重算一切稳定值）——
   所以 v16-a 的真实增益 = **把「载荷可解」绑定到「整套 VM+闸门+seal 链被忠实执行」上**：
   产物按编译期的 Delta 宿主模型生成转录期望值；运行期 SCHALL 的转录改为额外折叠
   宿主观测值（Vector3 tostring 折叠、typeof 折叠、IsStudio 布尔、identify 名长——
   **不混版本串、不混名串字节**，前者易变后者无熵）；观测不符 → 转录失配 → TOK 出错
   → `SLT → bdec st` 全链失步 → **解码出的只有毒字节**。打补丁 NOP 掉闸门同样失配。
2. **Phase-0（本轮已做）**：GateProbe v2 新增 `[XG-K1..K4]` + `[XG-KF]` 探针，
   只测量不进 PREDICT。**等真 Delta 回传这些行的实际值**，编译期宿主模型才落笔——
   R067 时代的教训就是没实测先拍脑袋，顺序不能反。
3. **Phase-1**：引擎接线（exguard 转录加项 + template 编译期模型参数化），
   新增开关先**不默认开**（如 `--key-host`），与现版产物并存对比；沙箱 prelude
   同步升级携带 K 系 mock。
4. **Phase-2**：Delta 双侧矩阵（开/关各跑 kkksu + 一个中型脚本）×2 轮稳定后，
   再决定 `--key-host` 是否翻默认并进入发布管线 hard 变体；同步重出锚点/测试/包。
5. **回退保险**：开关独立 + 锚点分表，翻车随时整开关撤离，R067.5 形态原地保留。

阶段准入门槛（Phase-1 开工前必须齐）：K1 名长与稳定性、K2 两个 fold 值、
K3 布尔包、KF 联合折叠——四门全部来自真 Delta，缺一不可猜。
